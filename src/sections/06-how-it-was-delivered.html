How the work actually gets delivered

Every project has run through the same five steps. It is not a formal framework; it is what works when you are one engineer serving eight departments and cannot afford to build the wrong thing.

  1. 01

    Find it on the floor, not in a backlog

    I spend time in each division and in accounts, HR and sales. Almost every project on the timeline started as somebody describing a task they disliked, not as an assigned requirement.

  2. 02

    Reverse-engineer the rules before writing any code

    Payroll had no rule book. The logic lived with one or two people. I ran repeated sessions with HR, accounts and payroll, wrote the rules down, and had them corrected until they were right. That document now belongs to the company, not to individuals.

  3. 03

    Prioritise openly on a shared board

    Requests from directors and engineers alike go onto one board in ClickUp, categorised and ranked. When two departments both want something first, the trade-off is visible rather than a private judgement of mine.

  4. 04

    Build on a branch, demo, correct, repeat

    Each feature is developed in isolation and shown back to the people who asked for it in short cycles: the same verification loop each time, against what they said they needed. Production is never the place where an idea gets tested.

  5. 05

    Ship it, then keep owning it

    Automated tests and code review run on every change, deployment is automated, and the desktop application on the PCB floor updates itself so nobody has to install anything. I remain the support line for all of it.
